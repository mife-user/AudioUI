### 1.1 新目标需求（草案，未实现）

> 本节记录用户提出的目标。第 2～13 节暂时保留现行 M2 基线，作为当前实现、原计划和历史验收的依据；二者冲突时不要把旧行为当作新目标，也不要把目标当作已经实现。新需求的优先级、批次和 M2 如何切换待用户确定，见 [路线图](dev/roadmap.md)；方案见 ADR-027/028。

**目标流程**：选题节点运行 Agent 并生成候选节点 → 连接提示词节点构建任务 → 连接 Agent 节点执行 → 已指定的输出节点，或依据 `reply` 自动生成的输出节点 → 后续预览、渲染和导出。

| 需求 | 目标行为 |
|---|---|
| F-04 选题目标 | 选题节点可直接运行 Agent；应用对选题结果进行校验并生成候选节点，用户从候选节点继续构建分支。候选节点是图节点，不是现行 M2 的候选端口。 |
| F-05 提示词目标 | 提示词节点只构建提示词与约束，不独立启动 Agent；后续连接 Agent 节点后才能执行任务。 |
| F-15 Agent 与输出节点 | Agent 节点运行任务；已指定输出节点时，其输出契约限定 `reply` 类型；无指定输出节点时，Agent 在应用允许的类型内选择，应用验证合法 `reply` 后自动创建对应节点并关联结果，不要求人工确认才能建节点。Agent 不获得通用建图权限。 |
| F-16 执行位置 | 通过统一的 Agent 能力支持本地或远程运行；本地客户端继续负责项目、上下文、节点与结果。远程时用户登录云端账户，由服务端校验用户和运行归属；Agent 在云端工作区使用自身工具，需要本地素材由用户选择上传。具体登录方式、部署和计费方案待评审，不表示已有服务。 |
| F-17 上下文与改挂 | 每次发送时按当前图关系重新构建上下文；改挂后新运行使用新路径。已发送运行保持其快照，旧结果保留原有来源；不得把旧结果静默归属到新路径。 |
| F-18 应用交互 | Agent 自身负责其具备的搜索、文件操作、Bash 等工具；AudioUI MCP 只负责经授权的应用交互，如 `reply` 和用户提问。不同 Agent 的工具能力可能不同。 |

**边界**：云端运行会发送任务上下文及用户选择上传的文件，不能称为“内容不上传”；同意范围、文件保存/删除、账户、资源额度与供应商授权需在上线前确认。输出必须经应用验证，非法类型/内容不得自动建节点。已有输出节点的覆盖/确认策略、多个后继的选择规则、旧工程迁移和视频产物采用前端代码或 DSL 等形式仍待决定，见 [ADR-027](decisions.md#adr-027-目标设计显式-agent-节点与应用控制的输出节点)。

## 2. 背景与问题

### 2.1 现状

内容生产被拆成四段：聊天里出选题和文案、文档里改稿、浏览器里生成素材、剪辑软件里成片。每段之间的上下文靠人搬运。

### 2.2 问题

| 问题 | 影响 |
|---|---|
| 流程不可见 | 不知道自己做到哪一步，返工多 |
| AI 结果不可复现 | 同一提示词两次结果不同，无法回滚 |
| 无法复用 | 每期从零开始，第二期不比第一期快 |
| 工具成本高 | 订阅制 AI 视频工具按月计费 |
| 数据不在本地 | 工程、素材、记录被平台锁定 |

### 2.3 为什么现在做

- Claude Code 的 stream-json 与权限协议可以驱动一次性运行，并由 App 注入上下文。
- WebCodecs + 浏览器 Canvas 可以本地确定性出片。
- 本机 MCP 可以让 Agent 以结构化方式操作工程。

## 3. 目标与成功指标

### 3.1 目标

1. 把「选题 → 脚本 → 画面 → 配音 → 导出」固化成一条可复用的链路。
2. 让 Agent 的每次产出可追溯、可应用、可回滚。
3. 让第二条同模板视频的制作时间显著低于第一条。

### 3.2 指标

| 指标 | Baseline | 目标 | 测量方式 |
|---|---|---|---|
| 第一条完整视频 | — | 完成首条完整视频 | 里程碑记录 |
| 单条视频制作时间 | 未测量 | ≤ 3 小时 | 手动记录起止 |
| 同模板第二条 | — | ≤ 2 小时 | 手动记录 |
| 连续更新 | 0 | 形成稳定更新节奏 | 发布记录 |
| 渲染失败率 | — | < 5% | 本地日志 |
| 运行中断可回看率 | — | 100% | 本地日志 |

> 本产品不采集远程遥测。以上指标通过本地日志与手动记录统计。

## 4. 用户与场景

### 4.1 目标用户

- 单人创作者，具备开发能力。
- 零预算或极低预算。
- Windows 11。
- v1 内容方向：音游作曲解析。

### 4.2 核心旅程

1. 新建工作台。
2. 输入一句想法，Agent 给出候选选题。
3. 从某个候选端口连线到提示词节点，建立该候选的分支；不同候选可各自分支，同一候选也可再分叉。
4. 在提示词节点写清产出要求。
5. 执行节点；App 构建上下文并启动一次运行；已有一运行在途时提示忙碌。
6. Agent 返回待应用产物。
7. 人工应用，产生新轮次。
8. 预览不满意，新增提示词节点继续。
9. 配音、导出。
10. 剪映精修后发布。

### 4.3 关键异常场景

| 场景 | 期望行为 |
|---|---|
| Claude CLI 未安装 | 启动提示安装指引，禁用 Agent 功能 |
| 运行中断 | 标记中断，运行历史可回看，重新执行节点 |
| 并发已满 | 进入队列，显示位置，可取消/调整顺序 |
| 渲染失败 | 保留旧预览，显示错误，不破坏工程 |
| 删除节点 | 预览影响面，级联删除下游，进回收站 |
| Agent 输出不合规 | 校验失败，保留原文，节点标红 |

## 5. 范围与非范围

### 5.1 Must（v1）

| 能力 | 说明 |
|---|---|
| 无限画布 | 平移、缩放、节点拖拽 |
| 树形链路 | 单主父；自由改挂；整条路径高亮；快捷栏切换 |
| 选题 | 输入想法 → 候选各有端口 → 连线即选择；一个候选可再分叉 |
| 提示词 | 结构化指令；执行后锁定 |
| Agent 运行 | stream-json；权限确认；每次节点执行一个一次性运行 |
| 待应用产物 | 人工应用后才改图 |
| 渲染 | 场景 DSL；预览；自动刷新 |
| 配音 | edge-tts；可关闭 |
| 导出 | 1080p30 MP4 + SRT + script.md |
| 并发与队列 | 上限 3；FIFO；可取消、可排序、可停止 |
| 删除与回收站 | 级联删除；24 小时回收 |
| 权限 | MCP 工具、文件写入、Bash 三档 |
| 绿色版 | 单 exe；数据在 exe 目录；zap 日志 |

### 5.2 Should（v1 后段）

- 日志面板与审计查询。
- 节点模板库。
- 渲染缓存与增量刷新优化。
- 运行用量与成本展示。

### 5.3 Not now

- 竖屏 9:16。
- 自定义节点类型。
- 剪映草稿自动生成。
- 本地 TTS 模型。
- 云端协作、账号、自动发布。
- 跨链路读取。
- 手动 `/rewind` 入口。

## 7. 业务规则与异常

### 7.1 规则

1. 图是单父森林：每个节点最多一个父；topic 必须无父且是树根；边不悬空。
2. 任意 prompt 节点（含其子树）可自由改挂到任意可用输出端口，允许跨 topic 树；成环、自连、topic 作子节点一律拒绝；运行/排队路径上的节点不可改；跨树时迁移子树 steps，失败回滚。同一父换候选同样视为改挂，需确认并标记子树 stale；同一父同一候选重复连接为幂等无操作。
3. 提示词节点应用首轮后锁定内容与执行；topic 应用候选后锁定内容与执行；锁定只冻结参数/内容与再次执行，非运行链的拓扑仍可改。锁定后继续迭代只能新增下游节点或从候选端口开分支。
4. topic 的每个候选是一个输出端口；连接某个候选端口的分支使用该候选，不再有单独的「选定」步骤。
5. 链是 topic 根到末端节点的派生路径；分支产生多条共享前缀的链；链不持久化。
6. 每次节点执行一个运行；运行与该路径绑定；上下文只含该路径祖先的最新轮次与 topic 候选项；运行之间不共享 Agent 上下文；并发按在途运行计数。超预算时先从远到近降级祖先，目标参数始终完整，仍超则拒绝；按引用读取 topic 产物也只能看到该路径所选候选。
7. 同一节点同一时间只允许一个运行。
8. 应用后的结果产物不可变，按哈希存储；待应用产物只有 UI 可以应用。
9. 工作区按 topic 树共享；写入只允许当前运行节点的增量目录；读取按当前路径叠加；其他 topic 树拒绝。上下文仅包含可见工作区文件的路径与大小，不自动注入文件正文；二进制资源只以路径引用。
10. 删除节点级联删除全部下游；增量与产物进回收站 24 小时。
11. 运行/排队中的路径节点只读；共享祖先只读；路径外的兄弟分支可编辑。
12. 任何写操作先校验后落盘；失败不得留下半成品。
13. 选中节点与切换链是视图操作，不改变图 revision、不广播快照；`activeNodeId` 仅用于恢复上次选中。

### 7.2 异常处理

| 异常 | 处理 |
|---|---|
| Agent 输出不符合 Schema | 节点标红，保留原文，不自动重试 |
| 应用重启时运行未完成 | 标记 `interrupted`，运行历史可回看，重新执行节点 |
| 改挂已有父的节点 | 提示影响面与上下文变化，确认后移动整个子树并标记下游 stale |
| 编辑运行/排队路径上的节点 | 拒绝并提示任务占用；路径外分支可编辑 |
| 编辑/再次执行已锁定节点 | 拒绝；提示新增下游节点或从候选端口开分支 |
| 渲染超时/崩溃 | 保留旧预览，记录日志，允许重试 |
| 磁盘空间不足 | 阻止导出，提示清理回收站 |
| 路径越界 | 直接拒绝，记录审计日志 |
| 应用产物时上下文已变 | 提示输入已变化，确认后仍可应用 |

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动 ≤ 3 秒（参考机）；1080p30 预览流畅；导出快于实时 |
| 资源 | 3 个活跃运行时内存 ≤ 1.5 GB；M2 全局单在途 |
| 上下文 | 默认预算 1,000,000 tokens；超预算按祖先降级或拒绝；记录估算与实际 usage |
| 可靠性 | 工程写入原子化；崩溃后可恢复；回收站 24 小时 |
| 兼容 | Windows 11 22H2+；系统 WebView2；不要求管理员权限 |
| 安全 | 仅监听 127.0.0.1；每运行独立 token；路径白名单；无远程遥测 |
| 隐私 | 不采集远程数据；日志仅本地 |
| 可用性 | 首次启动检测 CLI/WebView2；错误提示可执行 |
| 可维护 | 领域层可单测；适配器可替换；协议版本化 |

## 13. 假设与开放问题

1. v1 只做横屏 16:9、1080p30；竖屏 v2。
2. v1 内置 edge-tts，可关闭。
3. 产品名为 AudioUI（原名 Bili Studio）。
4. v1 节点集：topic / prompt / tts / render / export。
5. 并发上限 3 个在途运行；M2 为全局单在途，空闲休眠在 M5 评估；回收站 24 小时。
6. 链是 topic 根到末端节点的派生路径，不单独持久化；topic 候选端口连接即选择。
7. 许可证待定。
8. 最终视觉规范待定。
