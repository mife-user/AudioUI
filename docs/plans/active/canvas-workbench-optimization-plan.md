## 1. 本次目标与边界

**用户确认的新增方向**：

1. **连接**：节点不受创建先后或原有阶段顺序限制；任意阶段之间可建立有方向连接，允许一个节点有多个上游，但不允许自连或形成环。不能把该需求缩减为单父森林或仅支持 Prompt → Agent。当前图与运行实现仍是旧模型，目标方案未实现。
2. **重复生成与版本**：无指定输出时创建结果；指定空节点时写入该节点；已有结果默认先预览、确认后追加同节点版本，同时提供用户主动选择新建并行结果节点的入口。旧版本及来源保留，不自动运行下游。
3. **下游版本**：已有下游继续使用原版本；每个下游连接可分别固定版本，只有用户明确操作才切换。查看版本仅影响预览，不改变下游输入；“改用最新”是明确绑定操作，不隐含之后永远自动跟随。
4. **尺寸边框**：用户指的是选中节点后用于调整卡片大小的那一圈控制边框，不是要求移除普通卡片边框；移除该控制边框的视觉线，但保留尺寸调整能力和必要的局部控制点。
5. **运行原则**：独立 Prompt → Agent 的有效任务可以无 Topic 运行；自由连线与执行校验分离，按实际任务/工具检查本次选用的输入，不静默丢弃或删除不兼容连线；不自动运行上游。多输入来源、版本及输出目标在运行时冻结。
6. **Topic 重跑**：允许同一 Topic 再次生成候选；已有批次保留，新批次先预览并经用户确认后创建独立 Candidate，取消或失败不改变旧候选与下游。
7. **视频与 Agent**：RM-020 采用“可控画面 + 按需生成式素材”的混合评估方向，继续使用现有 Claude Code 适配，不先自研 Agent；该方向不代表视频能力已实现或纳入本批。[调研记录](../../dev/ai-video-workflow-research.md)列明来源与限制。

**仍待设计与评审**：多上游输入选择、角色与次序、共享祖先、工作区、权限和锁；Topic 参数及批次事务；视频供应商、具体技术、自动调用/导入的首个闭环范围及排期。原型中的“单主任务”只是 Agent 文本示例，不是所有节点的统一限制。

### 1.2 已完成的工作与未完成边界

- **输入中断与保存安全：代码和自动化自检完成，用户验收待定。** 修复前，Topic 与 Prompt 在自动保存期间会因全局 `mutationsDisabled` 变为 disabled；现已区分结构操作与输入禁用，不同节点参数写入串行，旧快照/回执不能覆盖较新草稿。
- 自动化覆盖停顿后继续输入与焦点、旧回执/快照、重新打开、跨节点保存、写盘/同步失败、工程切换、中文组合结束后最终文本，以及参数与位置回执乱序；前端 20 个测试文件 / 145 项通过，类型检查、lint、令牌检查、生产构建及 Go 全量测试通过。

- **真实 Wails/WebView2 页面自检**：Wails v3.0.0 / WebView2 157.0.4341.42，CSS viewport 1426 × 863、DPR 1.5。实测 Topic 自动保存后焦点与输入可用；通过 CDP composition 事件模拟中文组合并确认最终文本保存；工程切换时无效草稿触发保护，留在原工程后草稿保留，明确放弃后切换，重新打开原工程仍是最后一次已保存内容；关窗重试失败可留在应用或明确放弃，干净状态下关窗正常退出。截图：[关窗草稿保护实测](../../dev/evidence/u1-close-guard-webview.png)。
- **未覆盖边界**：CDP composition 是浏览器组合输入模拟，不等同于 Windows 原生 IME；未启动真实 Agent，AC-U-19 的目标路径实际运行仍以自动化覆盖为证。隔离工程数据、调试端口和本地服务已清理。U1 仍待用户验收；不得据此提前将独立批次标为已完成。

### 2.1 本次核对发现的具体缺口或风险

1. **已保存 Script 正文没有直接阅读入口。** `frontend/src/canvas/ScriptNode.tsx` 当前呈现版本、来源运行和 artifact 标识；节点未读取当前或历史 artifact 正文。原 M2-11A 设计演示的 Script 卡有结果预览。应作为本地脚本闭环可用性缺口处理，不等同于视频/导出需求。
2. **待确认数量可能投到错误的 Script 卡。** `flowModel.ts` 当前通过 pending 的 Agent `nodeId` 找当前直接 Script 来计数；但 `Pending` 保存的是发送时 `outputBinding` / `resultNodeId`，而 `PendingSummary` 未携带这两个字段。若结果待确认后原 Script 被合法改挂，原 Agent 后又绑定新 Script，计数可能显示在新 Script 上；后端仍会按冻结绑定拒绝不匹配的应用。需修正**展示归属**，不能只依赖实时连接。
3. **自动生成候选的排布可能重叠。** `internal/service/workflow/pending.go` 生成候选时固定使用 `Y + index × 160`；当前 `nodePosition.ts` 对 Candidate 预估高度为 235，实际 DOM 高度又取决于内容。长内容或尺寸调整后固定步长不保证避让，需要按实际/约定尺寸重新规划。
4. **自动保存失焦已在代码中修复，仍需真实产品页面验证。** 本文第 1.2 节列明已有自动化覆盖与未覆盖边界；不得声称 Windows 窗口实测通过。
5. **网页搜索不在当前内置工具声明中。** 原会话将其列为所需能力；本轮先核对 CLI 能力与权限/隐私边界，不把未来云端适配当成本地缺口的前提，也不将本地 Agent 的搜索工具错误地实现为应用 MCP 工具。
6. **既有 M2-12A/B/13 证据缺少真实浏览器交互截图。** 用户已确认阶段验收；缺的是该次自检记录的浏览器覆盖，不能倒推用户验收无效。本轮为新变更补齐可控页面验证，平台专有项目单列。
7. **运行前端屏障可能误把下游 Prompt 当作当前运行的路径。** `WorkspaceCanvas.tsx` 启动时取包含目标的整条叶子链并逐个 flush Prompt；若在 `Agent A → Script → Prompt B` 中运行 A，B 是下游而非本次上下文，B 的未保存/无效草稿可能不必要地阻止 A 启动。`flowModel.ts` 启动占位锁也暂时覆盖了整条叶子链。后端快照仍按根到目标构建；需要修正前端 flush/临时锁范围并补回归，不能把它误写成后端发送快照已证实错误。

## 3. 目标交互设计

### 3.1 卡片结构与尺寸

**推荐默认尺寸**（逻辑画布像素，正式值可根据真实页面微调；宽 × 高）：

| 类型 | 默认尺寸 | 首屏内容 | 主要动作 |
|---|---:|---|---|
| Topic | 280 × 250 | 标题、想法、方向、候选数及保存状态 | 生成候选；有异常结果时在右上角进入处理。 |
| Candidate | 235 × 160 | 候选标题、方向/开场摘要及来源 | 连接 Prompt；不能手工修改来源。 |
| Prompt | 280 × 230 | 标题、任务、约束和保存状态 | 编辑；连接 Agent；不直接运行。 |
| Agent | 235 × 165 | 运行状态、输出绑定、请求状态 | 运行；存在权限或问题时，右上角显示待处理数。 |
| Script | 270 × 205 | 版本、正文摘要和来源 | 右上角处理待确认结果；可查看完整正文与版本历史。 |

统一行为：

1. 标题栏固定，卡片正文在高度不足时内部滚动；关键按钮不能被裁掉。内容区和输入框的滚轮不应意外缩放画布。
2. 四条边和四个角可拖动；鼠标指针呈对应缩放样式。拖动左/上边时，卡片左上角位置与尺寸一起更新，右/下锚点保持不动。
3. 建议统一最小宽 200、最小高 140；最大宽 1200、最大高 900。超出限制时前端夹住，服务端验证有限值和合法范围；具体默认值与最小值可在真实页面验证后调整并写入设计令牌。
4. 缩放过程中只更新本地交互状态并实时重绘连接点；拖动结束时一次提交最终坐标与尺寸，不为每个鼠标移动写盘。
5. 键盘操作不能只依赖鼠标：卡片操作菜单提供“调整尺寸”数值输入与“恢复默认尺寸”；焦点可见，Escape 关闭并返回触发控件。
6. 尺寸是布局，不改变内容、连接关系、发送上下文、artifact 或 stale 状态；运行路径内容只读时仍可调整视图布局，具体与现有 `MoveNode` 规则保持一致。
7. 焦点、输入、按钮、拖拽和八向缩放相互隔离：标题栏拖动；输入区 `nodrag`；内部滚动 `nowheel/nopan`；缩放手柄不触发新建、连接或节点拖动。

### 3.2 输入与保存

- 编辑即更新本地草稿；停止输入 320ms 后调度自动保存。保存过程只阻止会与图状态冲突的结构/运行操作，不禁用本输入框。
- 输入法组合期间不提交未完成的组合文本；`compositionend` 后按最终文本保存。覆盖中文、换行、Emoji、粘贴和长文本，不在前端静默截断正文。
- 每个节点草稿有版本号；同节点写入保持顺序，旧 RPC、旧快照、切工程后的迟到响应不能覆盖较新草稿。
- 卡片显示「未保存 / 保存中 / 已保存 / 保存失败 / 已提交、等待同步」。保存失败保留内容和光标，允许重试；提交成功但拉取快照失败时只重试读取，不重复写。
- 启动运行前只 flush **根至本次目标节点（含目标）** 上需要保存的编辑，等待对应工程回执及权威快照；失败或未同步不得发送旧任务。下游及兄弟 Prompt 的无效草稿不能阻止当前运行；绑定输出仍按后端规则单独保护。
- 切换工程、关闭应用或可能卸载编辑节点之前检查未提交草稿：优先完成保存；失败时提供明确的继续等待/留在当前工程/明确放弃选择，不静默丢弃。关闭窗口拦截方式需先确认 Wails 事件契约。
- 运行锁、内容锁和真正的工程切换仍可禁止编辑，禁止原因需显示；不能为了消除失焦而放宽领域锁。

### 3.3 右键新建与连接

1. 画布**空白处**右键，出现「新建节点」菜单；新建位置是右键当时的画布坐标，而不是屏幕中心或最后一次选中节点。
2. 菜单列出 `选题`、`提示词`、`Agent`、`脚本`。候选项显示「由选题生成」，不可手工创建。新增的选题是独立根，其余是**未连接草稿**，不因为已有选中卡片而静默连线。
3. **现行实现**：提示词草稿可编辑；Agent/Script 草稿显示未连接与下一步说明，不可绕开后端启动或连接下游；连接到有效上游后解除相应限制。U14/U15 的目标已确认：独立节点可先连接，允许多上游；独立 Prompt → Agent 的有效任务可不依赖 Topic 运行，具体输入与授权仍须评审。目标实现前，不能把现状误写为已改变。
4. 鼠标在普通输入框/可编辑正文内右键时保留系统文本菜单。卡片上的其它右键动作不在本次默认实现范围；RM-002 中的节点右键和命令面板不因本项自动提前。现有双击聚焦已经在 `WorkspaceCanvas` 中实现，应保留并回归。
5. 使用 React Flow `screenToFlowPosition` 将 `clientX/clientY` 转换为画布坐标；考虑滚动、平移、缩放、负坐标和不同 DPI。菜单本身限制在当前视口内，但创建位置不因菜单避边而改变。
6. 用户明确指定的位置允许与已有节点重叠，不能悄悄挪到别处；创建后高亮新卡、保留现有 viewport，必要时给出遮挡提示。自动生成的节点另按第 3.5 节避让。
7. 去掉 `WorkspaceCanvas` 左上角「新选题」「草稿提示词」。底部快捷栏的“新链路”也应指向同一个菜单/可解释入口，避免保留第二套隐式居中创建语义；最终文案以评审为准。
8. 画布获得焦点后 `Shift+F10` 或键盘菜单键打开同一菜单，位置为视口中心或键盘焦点位置；上下键、Enter、Escape、点击空白可操作/关闭。空画布给出简短提示，不增加替代的左上角新建按钮。
9. 菜单提交防重复；调用现有 `AddNode` 并携带 `projectId`；成功后等待 receipt 对应快照。若命令已成功但同步失败，只允许重试同步，不能再次创建。
10. 真正的连接/改挂依旧经 Go 命令校验。无效类型、环、自连、跨工程、运行锁或第二个 Script 输出被拒绝时，画布不乐观增加边；改挂继续显示影响面和确认。

### 3.4 悬浮 Agent 栏与节点内确认

**布局**

- 默认显示右上角小型 Agent 状态胶囊：运行状态、待处理数量、展开按钮；不占画布列宽。
- 展开为悬浮窗口，建议默认宽 360，窄窗口宽不超过可用视口减 24；高度不超过可用视口，长对话、长命令、错误和元数据可滚动、换行。不能被底部叶子链遮挡。
- 面板保留运行列表、当前/历史 transcript、工具调用、状态、用量、停止运行和定位相关节点；没有自由提示词输入框。关闭面板不停止运行、不清除未决请求。
- 请求数量、正在运行和错误需用文字及图标表意，不只靠颜色。窄窗口可改为屏内抽屉；各状态保持键盘可达和焦点回收。

**请求归属与操作**

| 请求 | 正常归属 | 卡片右上角入口 | 约束 |
|---|---|---|---|
| 新版 Script 待确认 | `Pending.outputBinding.nodeId` / `resultNodeId` 指向的冻结输出 Script | `待确认 N` → 查看新内容、旧/新来源、基准版本 → `确认追加` / `丢弃` | 后端重验绑定和基准；版本冲突不可 force；取消预览不等于丢弃。 |
| 无效 Script 输出 | 冻结目标存在时关联目标；否则发起运行的 Agent | `错误/待处理 N` → 原始输出与校验错误 | 只能丢弃或关闭查看；不能确认不合法内容。 |
| Topic 相关待处理/无效结果 | 发起运行的 Topic | `待处理 N` → 原文与允许操作 | v2 合法 `topics` 仍自动生成候选，不新增应用步骤；兼容现存历史 pending。 |
| 工具权限 / `ask_user` | 对应 `runId` 的发起 Topic 或 Agent | `请求 N` → 完整请求与明确应答 | 按 `runId + requestId` 处理；保留三档策略、超时与审计；不能因悬浮面板关闭而自动允许。 |

- 运行面板只给出未决数量和“定位节点”；普通路径不再要求去狭窄侧栏查找结果并应用。定位会选中并将卡片移入视野，但不能创建或修改节点。
- 有多个请求时逐项显示，处理特定 ID；不得以最新运行或当前选中节点替换请求归属。工程切换、重复事件、run seq 缺口和迟到响应必须按现有 scope/快照恢复处理。
- 若冻结目标已被改挂、不可见或不存在：优先定位其原 Script；若原节点无法定位，回退到发起运行的卡片；两者都不可定位时提供明确的异常恢复列表/错误，不得让未决请求消失或把它归给另一个 Script。
- “查看”可随时关闭；`确认追加` 才提交。操作中禁用重复点击；提交成功但刷新失败显示“已提交，仅重试同步”。

### 3.5 连线、分支与叶子链

- **画布连线**：默认使用低对比中性线、方向箭头和端口；当前路径用更清晰的线宽/强调色；未关联分支弱化但仍能看见。颜色之外保留线型、箭头、状态文字/图例。
- **状态**：默认、悬停、选中路径、运行路径锁、连接拖拽中、无效目标和错误均有可区分外观；`prefers-reduced-motion` 下不使用持续流动动画。
- **可操作面积**：视觉线细，实际命中区域更宽；端口可聚焦并有可访问名称。键盘连接/改挂继续保留，不能只提供鼠标拖线。线条点击只做选择/定位/展示关系，不新增未规划的删除语义。
- **U7 历史几何（U10 已替换折线路由）**：U7 时近距离正常左右连接采用平滑曲线；反向或相邻节点之间空间不足时采用有界折线/绕行，避免从无关卡片正文穿过。算法只改变路径绘制，不改变真实父子关系；节点位置或尺寸改变时更新端口测量与边。U10 当前将反向、狭窄与绕障路径改为带圆角的复合曲线，拖线预览共用路由。
- **分支**：共享前缀只绘制一次，选择叶子链时高亮该叶子的完整后端路径；高亮的选择与运行锁不是同一个状态。不存在/未测量 Handle 时延后绘制，回归错误 008/015。
- **快捷栏**：保留 Go 返回的 `WorkspaceSnapshot.chains`；每条路径显示可辨识的末端标题、状态和必要摘要，长标题可展开/提示。列表可横向滚动、收起；选中切换只调用 `SelectNode`，不递增图 revision、不占运行槽，也不重拉整个快照。
- **新节点自动排布**：用户右键指定坐标不强制避让；应用自动生成的 Candidate/Script 必须按确定性规则考虑既有节点矩形、新节点默认尺寸、用户保存的尺寸和间距，避免新增候选互相覆盖。不能自动移动用户已有节点；空间不足时使用可解释的下一位置而不是改变图结构。

- **先复现、不预设根因**：当前 `TopicNode.tsx` 将候选行和其 source Handle 放在同一个 `.canvas-node-content` 滚动区；`flowModel.ts` 按候选节点创建边，Handle 可被测量但内容可能滚出可视区域。这是可能原因，仍须用小尺寸、滚动、缩放和实际生成结果复现；同时检查候选卡是否被其他卡遮挡或位于视口外，不将未验证现象当成已证实根因。
- **折叠设计建议**：五类节点均有可键盘操作的折叠/展开入口，折叠后仍显示类型、标题、必要状态、请求入口和可见连接点；只隐藏正文，不修改内容、来源、连接或运行状态。建议按工程保存折叠状态，并将展开尺寸与折叠后的显示高度分开：收起不覆盖原有 `size`，展开恢复原尺寸；收起态允许移动，不提供八向缩放，先展开再调整尺寸。纯视图变化不得改变上下文语义或 artifact。
- **输入与请求**：折叠时不卸载并丢弃 Topic/Prompt 本地未保存草稿或 IME 组合；保存中、失败、运行锁和待处理请求仍能看见并恢复；无需通过折叠触发保存、运行或取消。持久化/同步失败须保留可见状态并明确提示。
- **候选方案建议**：将 Topic → Candidate 的自动关系改用卡片边缘固定可见的汇总锚点，不再把出线端点放在可裁剪、可滚动的候选行内；多个候选可以共用锚点，但目标 Candidate 和来源索引仍分别对应真实节点。汇总锚点是否可手动拖线可按实现设计，但不能因此移除 Topic 的 U14 手动连接能力。标题区保持候选数，正文列表可滚动，并提供可定位各 Candidate 的入口；折叠时先展开即可访问列表。候选在视口外时可定位而不悄悄移动节点；读取中或失败时明确呈现，不能虚构候选或消失已有真实关系。
- **布局与同步**：折叠/展开、卡片滚动、视口缩放、尺寸变化后更新 React Flow Handle 和节点测量，连线从可见锚点到真实目标；测量未就绪不渲染幽灵边。路由避障使用当前显示尺寸；自动生成节点避让仍考虑展开后保存尺寸，避免因折叠自动占据原空间而展开重叠。折叠不会自动移动其他卡片。
- **涉及/验证**：`TopicNode.tsx`、`CandidateNode.tsx`、其余节点、`flowModel.ts`、`useMeasuredNodeHandles.ts`、`WorkspaceCanvas.tsx`、`workspace.css`，以及折叠状态所需的工程布局数据/命令和测试。覆盖 3～10 候选、200×140 小卡、滚动、折叠/展开、移动/八向缩放、工程重开、迟到数据、缺失结果、遮挡/定位、自动保存与运行锁。出口 AC-U-24～26（草案），回归 AC-U-01～07/11/15/17。

### U14：任意阶段连接与多上游无环图（目标已确认，未开始）

- **用户确认的连接规则**：不限制节点创建或连接先后，也不按现有 Topic → Candidate → Prompt → Agent → Script 固定阶段顺序限制；同工程内各阶段节点可作为有方向的连接起点或终点，同类型的不同节点也不因类型相同而禁止连接。允许一个节点有多个上游、一个上游连接多个下游；禁止自连及任何直接或间接成环。形成多上游汇合后，不得替换或丢失原有输入边。将来经评审纳入的其他阶段也沿用此图结构原则；本计划不因此提前实现视频节点。
- **必须覆盖的例子**：先独立新建 Prompt 与 Agent，再手动连接；或者先建 Agent、后建 Prompt；`Prompt A → Agent C ← Script B` 多上游同时保留；连接非相邻阶段或两个同类型节点；若已有 `A → B → C`，尝试 `C → A` 必须拒绝且图不变。Candidate 由 Topic 生成的原始 artifact/index 来源必须保留，普通连线本身不得篡改来源身份。
- **现状与冲突**：`PromptNode.tsx` / `flowModel.ts` 在无父时隐藏输出；`internal/service/workflow/service.go` 连接时调用 `chainRoot`；`internal/domain/entity/graph.go` 使用单 `parent`、Topic 根和单路径。现有 ADR-020/027/029、AC-T-19 与用户确认的新目标冲突；旧规则仅描述已验收的当前实现，新目标见 [ADR-030 草案](../../decisions.md#adr-030-多上游无环图与版本引用草案)。
- **设计与实施**：将图从单父森林演进为有向无环图；设计支持多个输入的显式边、持久化、稳定标识及版本引用，不能只调整前端或由前端复制业务规则。Go 命令层校验工程范围、端点、自连与环，图变更原子提交；前端各阶段提供手动输入/输出入口和键盘等价操作，并按权威快照绘制全部真实边。数据格式可按已确认的开发期策略演进。
- **运行边界**：连线阶段不再按旧类型矩阵拒绝，但并不假定任何连接组合都具备可运行的任务或输出；多上游上下文、输入类型、版本、授权、工作区、运行锁及错误提示须在 U15/ADR 完成设计。不能交付一个新图格式却使现有已验收的单路径运行失效；切换与验证策略在实施前确定，未就绪时须明确说明，不能假报成功。
- **涉及/验证**：`internal/domain/entity/graph.go`、`internal/service/workflow/{service,validate,locks,workspace}.go`、快照/工程持久化、各 `*Node.tsx`、`flowModel.ts`、`WorkspaceCanvas.tsx`、`ChainQuickBar.tsx` 及 Go/前端测试。覆盖多源汇合、任意阶段、同类型不同节点、孤立子图、跨工程、自连、长环、重复请求、运行锁、失败回滚及重开；同一上游经多条路径汇合时不得遗漏输入或重复提交，具体上下文去重规则留 U15。
- **出口**：AC-U-27～28、AC-U-36；新图及运行适配完成评审并覆盖原单路径回归。M2 历史验收事实保留。

### U15：无 Topic 与多上游图的运行、上下文及工作区（目标原则已确认，未开始）

- **现状与目标**：当前 `Graph.SnapshotForRun`、workflow 运行锁和工作区按 Topic 根及单一路径工作。目标允许独立 `Prompt → Agent` 在任务有效时直接运行；Prompt 仍只保存任务，由 Agent 发起运行，不伪造 Topic/Candidate。运行需要完整输入和输出契约；空任务提示补充，不能以画线成功冒充运行成功。
- **连接与执行分离**：连接时遵循 U14 的任意阶段多上游无环目标；执行前按目标任务、执行工具和本次已选输入检查内容、版本及参数组合。缺失、不兼容或失败的已选输入须明确说明，不自动丢弃、不删除连线；用户可调整可选输入后重试。运行下游不自动重新运行上游；旧有效版本仍可显式选择，最近失败状态不得伪装成新结果。
- **多上游上下文**：运行前明确实际参与的直接输入及必要祖先、来源版本、角色与次序；不得仅取一条父路径或静默混入其他输入。共享祖先的相同版本可避免重复载入正文，但保留各来源关系；不同版本或角色不能盲目合并。多 Prompt 的优先级、约束冲突与人工处理须明确；原型“一个主任务”的检查只是文本任务示例，不限制所有节点，视频/音频合成等无需强制 Prompt。
- **快照与输出**：发送时冻结实际输入、各连接的精确版本、必要来源、任务和输出目标；多个输出候选时明确选择，不按位置猜测。无指定输出、空输出及已有输出分别遵循 U16；改线、预览或新版本不改旧运行，不得让迟到结果写入其他目标。
- **工作区与安全**：无 Topic 时须有项目内工作区；多个 Topic 根汇合不自动授予全部文件读取权限，同名素材须按来源区分并明确处理，不以叠加顺序静默覆盖。工作区身份、可授权范围、迁移/回滚、运行锁和叶子/子图视图由 ADR 确定；Bash 协作式门禁不冒充 OS 沙箱。
- **设计与验证**：先补全 ADR-030、同步 `architecture.md`、`agent-protocol.md`、`CLAUDE.md` 及验收，确定输入选择默认值、事务、切换及单路径回归；再使用离线 fake Driver 覆盖无 Topic、多个上游、共享祖先、不同版本/角色、两个根、输入缺失/不兼容、输出目标、权限与快照。真实 CLI 或联网测试需另行授权。出口 AC-U-29～30、37～39、41～43；AC-U-40 在不需要自然语言任务的执行契约纳入后适用，不预设视频功能在本批实现。
- **涉及**：`internal/domain/entity/graph.go`、`internal/service/workflow/{locks,service,workspace,agent_tools,pending}.go`、`internal/service/context/builder.go`、`internal/service/run/manager.go`、`internal/infra/paths/run_guard.go`、工作区与前端运行前保存/图视图。

### U16：重新生成的结果、版本与下游分支（核心策略已确认，未开始）

- **现状（不是新方案）**：Agent 无指定 Script 时，合法结果自动创建一个 Script；指定空 Script 时自动写入首版；指定 Script 已有版本时，结果先待确认，确认后在同一 Script **追加不可变版本**。Script 卡可阅读历史版本，但运行快照目前取祖先 Script 的**最新版本**；阅读历史不改变下游使用版本。一个 Agent 当前最多一个直接 Script 输出。Topic 成功生成候选后锁定，不支持同一 Topic 再次生成。
- **已确认的目标**：无输出时自动创建；指定空输出时写首版；已有输出时默认先预览、确认后追加版本，并提供显式“新建并行结果节点”入口。每个下游输入连接固定具体来源版本，生成新版本不自动更改已存在的引用；用户可以明确将某条连接改为其他版本。预览标签与实际输入绑定分离，旧运行快照、结果和版本不可被覆盖。
- **具体含义**：已有 `Script v1 → Prompt A` 之后生成 v2，A 仍绑定 v1；用户可让 A 改用 v2，也可另建 Prompt B 绑定 v2。对新建连接，建议初始明确显示并固定当时选定的版本；尚无版本的输入标为未就绪，绑定时机须在运行设计中确认。“改用最新”指明确选择操作时的最新版本，之后出现 v3 不自动切换。
- **并行输出**：用户主动选择新建结果节点时，原结果及其下游保持不变；需改变当前 Agent 至多一个直接 Script 输出的限制，并明确一次运行的目标绑定、待确认预览、重复提交与新建失败的事务，不得悄悄替换已有节点。
- **候选重跑**：允许 Topic 再次生成；已有候选时先预览新批次，确认后原子创建独立 Candidate。旧 Candidate 的 artifact/index 来源、运行和下游保持不变，不按标题或索引覆盖；取消或失败不改旧批次。相同 artifact 可复用，但主动新运行仍要有独立批次/运行来源；首次生成沿用现有自动提交。允许编辑哪些 Topic 参数、批次身份及事务细节待评审。

#### 场景与确认状态

| 场景 | 已确认方向 / 尚待讨论 | 必须说清的影响 |
|---|---|---|
| 1. 首次运行，无后续输出 | 自动创建结果节点。 | 合法结果和新节点原子提交；失败不留下空壳。 |
| 2. 用户预先连接了空 Script | 写入已指定的空节点。 | 不能同时写旧节点又新建，也不能写到未指定的相邻节点。 |
| 3. 已有 Script v1，Agent 生成新结果 | 默认预览、确认后追加 v2；用户也可明确选择另建并行结果节点。 | 现有单直接输出限制需调整；要冻结本次选定目标。 |
| 4. Script v1 已有下游，随后产生 v2 | 原下游保持 v1，用户可明确将某条输入改为 v2。 | 不将旧结果伪装成由 v2 产生；原运行快照不变。 |
| 5. 用户点 v1/v2 标签 | 仅切换正文预览；“供某下游使用”是单独的明确操作。 | 应显示预览版本、实际输入版本与来源。 |
| 6. 保留 v1 的下游，又用 v2 创建新方向 | 各下游可绑定不同版本；用户也可显式新建并行结果。 | 多上游 DAG 中按每条连接记录输入版本；不能只按节点保存一个全局版本。 |
| 7. Topic 已生成候选后再次运行 | 允许重跑；新批次先预览、确认后创建独立 Candidate，取消不改旧批次。 | 数量和顺序可能不同；旧 Candidate 来源和旧分支不得被覆盖，同内容新运行仍保留独立批次来源。 |
| 8. 新结果不合法、运行失败或用户取消 | 保留旧节点/旧版本，新结果报错或待处理。 | 不自动覆盖、误删、自动重试或自动执行下游。 |
| 9. 同一个请求重放 vs 用户主动再次运行 | 同一运行同一请求幂等，主动新运行保留独立来源。 | 内容相同可复用 artifact，但不能丢运行记录或误重复提交。 |
| 10. 结果生成期间上游或目标发生变化 | 沿用发送快照、运行锁和冲突保护；多上游锁粒度待 U15 设计。 | 旧结果不能静默写入其他节点，版本基准变化不能强制覆盖。 |
| 11. 删除、隐藏或回退旧版本 / 结果分支 | 先保留并允许查看；删除方案尚未纳入。 | 下游、历史运行、待确认结果和 artifact 引用不能悬空。 |
| 12. 结果类型不止 Script | 本批仍按现有 `script@1` 实现；未来视频类型的版本策略待单独设计。 | 不提前实现视频，也不假设所有节点都适合同一种版本规则。 |

- **DoR/影响**：版本、分支与 Topic 新批次方向已确认；运行时多上游引用与合并、输出目标及候选批次事务仍待设计。先完成 ADR-030，并同步 PRD、架构、Agent 协议、验收、前端设计及 `CLAUDE.md`；评估 `internal/domain/entity/{graph,project,run}.go`、`internal/service/workflow/{pending,service,agent_tools}.go`、`internal/service/context/builder.go`、持久化和相关画布节点。不能只改版本标签。
- **测试/出口**：离线受控 Driver 覆盖首版、已有版本确认/取消、显式并行输出、不同连接引用、预览不改绑定、相同内容不同运行、失败/重放幂等、锁与改线后的冻结快照；覆盖 Topic 重跑的不同数量候选、取消、来源稳定、旧分支、相同 artifact 新运行和重开。验收为 AC-U-31～35；真实 Agent 和联网测试另行授权。

## 5. 验收标准（Given / When / Then）

| 编号 | 验收场景 |
|---|---|
| AC-U-01 | Given 正在编辑 Topic 或 Prompt，When 停顿超过 320ms 而自动保存开始，Then 输入框不被禁用、不丢焦点，继续输入与光标位置正常。 |
| AC-U-02 | Given 首次保存仍在途且用户继续输入，When 旧回执和旧快照先到，Then 最新草稿不回退；最终保存最新内容，重新打开工程后内容一致。 |
| AC-U-03 | Given 中文输入法正在组合、粘贴长文本或输入 Emoji，When 自动保存计时触发，Then 不提交不完整组合、不截断内容、不重复字符。 |
| AC-U-04 | Given 写盘失败、快照同步失败、工程切换或启动运行，When 仍有未保存/未同步草稿，Then 草稿保留并提示；运行不能使用旧值，提交成功的操作不重复写。 |
| AC-U-05 | Given 任意五类卡片，When 从四边及四角缩放，Then 对应指针、边界和锚点正确，正文可滚动，端口/边跟随，不误触拖动与连线。 |
| AC-U-06 | Given 使用当前开发格式的工程已调整卡片大小和位置，When 关闭并重新打开该工程，Then 两者一致恢复；既有开发工程不要求迁移或兼容。 |
| AC-U-07 | Given 运行路径已锁定，When 用户只调整卡片布局，Then 内容/拓扑锁仍有效，而视图调整不改变上下文哈希、结果绑定和内容。 |
| AC-U-08 | Given 画布已平移或缩放，When 在空白处右键并选 Prompt，Then 新草稿左上角位于该右键的画布坐标，不隐式连接、不自动挪到屏幕中心。 |
| AC-U-09 | Given 菜单靠近窗口边缘或使用键盘，When 打开并选择类型，Then 菜单保持可见，方向键/Enter/Escape 可用；输入框右键仍可使用文本菜单。 |
| AC-U-10 | Given 空画布，When 用户需要创建节点，Then 左上角无原有两个创建按钮，但右键和键盘可创建；Candidate 标明由 Topic 自动生成。 |
| AC-U-11 | Given 已有 Script v1 收到合法 v2 结果，When 点击原输出卡片右上角待确认入口，Then 可查看内容、目标和基准并确认追加或丢弃；确认后 v1 保留，版本冲突不提供 force。 |
| AC-U-12 | Given 待确认结果绑定旧 Script，When 该 Script 改挂且 Agent 后接入新 Script，Then 待确认标识仍指向冻结目标/异常恢复路径，不误指新 Script；后端拒绝不匹配确认。 |
| AC-U-13 | Given 长 transcript、很多分支和窄窗口，When 展开悬浮 Agent 栏或缩放画布，Then 面板内容可完整滚动、操作可达；卡片、端口和线条没有被固定侧栏挤出不可访问区。 |
| AC-U-14 | Given 多条共享前缀的叶子链，When 切换或移动/缩放节点，Then 高亮的路径、箭头和端口正确，非当前分支仍可辨认；切换不改图 revision、不占运行槽。 |

| AC-U-19 | Given `Prompt A → Agent A → Script A → Prompt B` 中 Prompt B 有未保存或无效草稿，When 用户启动 Agent A，Then 仅 flush 根到 Agent A 的相关输入，Prompt B 不被强制保存或阻止本次启动；提交阶段仅临时锁定该前缀及须保护的绑定输出 Script A，Prompt B 和其他无关分支不被误锁，最终以 Go 的权威锁为准。 |

### 6.1 实施阶段离线门禁

在 `AudioUI/` 目录执行，禁止自动下载；先运行受影响文件的聚焦测试，再运行完整门禁：

```bash
export GOPROXY=off GOSUMDB=off npm_config_offline=true
go vet . ./internal/...
go test . ./internal/...
wails3 generate bindings -ts -i -clean=true
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend run check:tokens
npm --prefix frontend run test

wails3 build
git diff --check
```
