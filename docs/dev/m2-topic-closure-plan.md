## 1. 执行方式与边界

每次只执行下表一项，完成代码、测试、相关文档及证据后交用户验收，再进入下一项。子项是对现有任务卡的细分，不另改已验收任务；原任务只有其所有子项通过用户验收后才标记完成。任务记录统一使用 `docs/dev/evidence/<任务编号>.md`，记录实际命令、结果、未覆盖项与 AC 映射，完成实现后状态为「待验收」，不自我宣布验收。

| 顺序 | 任务 | 原任务映射 | 依赖 | 可独立验收的结果 |
|---|---|---|---|---|
| 1 | M2-08A 快照与事件恢复契约 | M2-08 | M2-01～07 已验收 | 后端快照、事件和恢复测试可用 |
| 2 | M2-08B 工作台与运行控制台 | M2-08 | 08A | 工程切换、运行历史与请求交互可用 |
| 3 | M2-09 画布与节点连接 | M2-09；提前完成部分 M2-12 运行锁展示 | 08B | 画布新增、连接和改挂等图交互可用 |
| 4 | M2-10A 选题参数与启动运行 | M2-10 | 09 | 保存选题参数并启动一次性运行 |

## 2. 开工前事实与接口约定

- 当前前端入口仍挂载 M1 `SessionPage` 和 `agentStore`。后端已有工程、图命令、pending 和 run handler，但尚无 `GetWorkspaceSnapshot` 或 `workspace:changed` 接线；`workflow.Options.OnChange` 尚未注入事件桥。
- 已有 `GetRun` 返回持久化 `RunRecord`，不包含活动运行的事件序号或未决权限/问题；运行事件也没有 projectId。仅调用现有 `GetRun` 不能实现无缺口恢复。候选计数从 artifact 读取，但前端尚无读取已应用候选内容的接口。
- 工程图 `project.revision` 是持久化 revision，`SelectNode` 不改变它；运行路径锁是内存状态。工作台同步版本须与工程 revision 分开，不能为了运行锁而伪造工程写入或改变图 revision。
- 不假设 `Start` 返回早于事件：它完成初始化并提交首条消息后才返回，开始、请求及完成事件可能在返回前到达。`GetPending.rawPayload` 按生成绑定的实际类型解码，不能未经验证直接假设是普通字符串。
- UI 预检不替代后端校验。节点内容锁与运行路径锁是两种状态；应用后内容/执行锁定，但非运行路径上的合法拓扑改挂仍可用。题目候选数 UI 采用 3～10 的整数，与已实现 topics Schema 对齐；后端已有参数校验只拒绝负数，不改变历史存储或宣称已有更严格服务端约束。

### 同步契约（08A 实现，08B 消费）

1. 增加 `GetWorkspaceSnapshot()`，返回 `{revision, snapshot}`。`snapshot` 包含协议 §10.1 的 project、nodes、pending 摘要、runs 摘要、Go 派生 `chains` 和 `lockedNodeIds`；不内联 transcript、pending 或 artifact 正文。`snapshot.project.revision` 保持持久化图 revision；外层 `revision` 为本进程单调递增的工作台版本，覆盖工程切换、图/pending 变更和运行锁变化，不落盘。重启或重新订阅以新快照为基准，不跨进程比较该版本。修改协议及架构文档消除两种 revision 的歧义。
2. 发布 `workspace:changed`，包含 `projectId`、工作台 `revision`、`reason`（`project`/`graph`/`pending`/`run_lock`）和当前工程图 revision；新增 `projectId` 到 `run:<type>` envelope。项目创建/打开、图与 pending 成功提交、锁取得/释放均接线；失败及幂等无操作不伪造图修改。`SelectNode` 不发图事件；本地选中成功后持久化，失败恢复并提示。
3. 建立一致的发布/读取顺序：快照内各部分属于同一工程且对应返回的工作台版本；切换工程或快照读取中发生变更时重试或明确返回可重试错误，不返回混合工程数据。锁、版本与事件的更新要有清晰同步边界，避免回调持锁重入死锁；测试覆盖并发提交、切换与锁变化。
4. 增加 `GetRunSnapshot(runId)`：返回 runId、projectId、当前完整 run 视图、与该视图同一同步点的 `lastSeq`，以及活动运行尚未解决的权限/问题请求；终态及历史运行提供持久化记录、空请求列表。为此在运行管理器内同步维护活动请求、transcript 和事件序号；请求解决/超时/运行结束时移除，历史运行不恢复请求。保证状态更新和序号原子对应，事件发布可在解锁后进行；保留现有 `GetRun` 兼容调用方，不改已有磁盘格式。
5. 前端先订阅事件并按工程加载代次缓冲，再取工作台快照及所需运行快照；应用快照后只按对应版本/seq 重放更新。相同或较旧事件去重；出现缺口时暂停应用该流并重拉，缓冲重放期间再出现缺口则继续重拉；失败保留可见错误与重试入口。工程切换或卸载时递增代次、清理订阅及缓存，丢弃旧工程事件和迟到响应；不以 nodeId 或 treeId 冒充 projectId。
6. 运行重同步使用活动快照的 `lastSeq` 避免流式文本重复；权限/问题请求以快照为准，再重放更新。终态历史只读；使用 runId 路由停止、权限和问题应答。不得将未知实际 token 用量显示为 0。

## 3. 逐项任务卡

### M2-08A：快照、事件与恢复契约

**状态：已验收**（用户于 2026-11-03 确认；任务级 Go、前端、绑定生成与 Wails 构建门禁通过；AC-01/03/06 仅有接口级自动化覆盖，无 GUI/live CLI；见 [M2-08A 证据](evidence/m2-08a.md)）

**实现**

- 在应用接线层组合 project、workflow、run 及 artifact 相关服务，提供上述工作台快照；复用 `Graph.LeafChains`，链不落盘。pending/runs 使用摘要；状态按现有运行和 pending 数据推导，路径锁从 workflow 取得。
- 接入工程、workflow 和运行锁变更事件。回调必须带变更所属 projectId，不能在锁内通过再次查询当前工程推断归属；完善启动/结束、启动失败和工程切换时的版本与事件。
- 增加运行快照和请求跟踪；权限、问题的到达、响应、超时和终止都与事件序号一致。补充活动运行与项目身份映射，历史查询仍受活动工程约束。
- 更新 `agent-protocol.md` §10、`architecture.md` 中快照、订阅顺序、事件字段和两类 revision 的说明；同步绑定并更新本计划涉及的任务手册。

**测试与出口**：Go 测试覆盖空/有工程、叶子链派生、pending 摘要、路径锁、工程切换隔离、项目/图/pending 事件、无效/幂等命令、锁释放；用并发测试验证快照读取与事件序号的原子一致性，模拟流式片段、权限到达/解决/超时、开始即结束和订阅期间发生的变更。确认旧 `GetRun` 与既有运行/持久化测试仍通过。此项不实现 UI；AC-01/03/06 仅记接口级证据。

### M2-08B：工作台骨架、工程与控制台

**状态：已验收**（用户于 2026-11-03 明确指定截图更名后即算完成验收；截图及自检结果见 [M2-08B 证据](evidence/m2-08b.md)）

**实现**

- 新建工作台与运行 API 封装、Zustand stores 和桥接 hook，按第 2 节契约加载、订阅、重同步并隔离工程；工作区无工程、加载中、错误及可重试状态均可见。
- 工程入口支持列表、新建、打开；保留应用现有环境检查、系统抽屉与关于入口。运行在途时禁用切换，并处理后端 `BUSY` 竞态；切换后加载该工程快照和运行历史。
- 控制台按 runId 分组并查看流式 transcript、工具事件、运行状态、开始时间、上下文哈希及估算/实际 tokens；支持中断及权限/问题应答。复用现有卡片行为，包括问题的「其他」回答；控制台不提供自由聊天输入。历史运行只读，待处理分页先提供空状态。
- 用工作台替换 M1 页面和事件桥，移除仅属于旧自由聊天/恢复入口的 UI 与测试，保留仍由系统页或权限/问题卡使用的代码；不手工编辑生成绑定。

### M2-09：画布与节点连接

**状态：已验收**（用户于 2026-11-04 在隔离工程的生产 Wails 窗口中手工新增 topic 与草稿 prompt，确认工程 revision 与节点数增长、界面显示已同步、6 个节点可见且不重叠；自动化与构建门禁通过；见 [M2-09 证据](evidence/m2-09.md)。本项不包含真实 topic 候选读取、选题运行或应用。）

**实现**

- 安装并锁定 `@xyflow/react`，受控渲染 topic/prompt、草稿和后端快照派生的边；空画布可新建 topic，支持新建未连接 prompt，以及从合法输出端口新增 prompt。平移、0.6～1.6 缩放、重置视图、双击聚焦与位置去抖保存；选中节点调用 `SelectNode`，不重拉快照。
- 图命令按发起时 `projectId` 执行并返回 `{ projectId, projectRevision, nodeId }` receipt。前端只在权威快照同时满足工程、工程 revision 和目标节点后报告同步完成；命令已提交而快照失败时保留错误与 receipt，阻止重复写入，仅提供快照重试。工程切换清除旧工程等待状态，同工程快照不覆盖本地选择。
- 新节点位置按节点占位矩形避让，快照确认后聚焦；首次打开/切换工程时只 fit 一次，普通刷新不改视角。工作台主区与 React Flow 根使用确定的 flex 高度链和绝对填充。鼠标与键盘选择/移动都走持久化回调；改挂提交期间禁用取消、背景关闭与 Escape。
- topic 应用前无可用候选端口；本任务使用可控测试 fixture 验证候选 handle，真实候选读取在 10B 接入。prompt 提供输入/输出端口，草稿只能作为连接目标且不可执行。路径高亮依据当前选中节点及后端图关系，叶子链快捷栏留至 M2-12。
- 连线与改挂走 `Connect`：先以 `replace=false` 请求，遇 `REPARENT_CONFIRM_REQUIRED` 时显示子树数量、跨树/steps 迁移及旧上游提示；同父换候选显示旧→新候选。确认后使用 `replace=true`；取消、拒绝或错误不提交本地边，同父同候选幂等。跨树/运行锁等约束由后端最终裁决。
- 区分内容锁和运行路径锁；路径锁禁止参数、拓扑和新增子节点，路径外兄弟可编辑；锁定内容不阻止允许的拓扑操作。交互需有键盘可达的节点选择、操作和连接替代路径，并显示错误/状态。

**测试与出口**：画布自动测试覆盖缩放边界/重置/双击聚焦、节点位置防抖与失败回退/切换工程取消排队写入、草稿端口、候选端口 fixture、工作台派生边、topic/prompt 新增、键盘连接与改挂、跨树及同父换候选确认/取消/失败、运行路径锁和内容锁差异、非法目标和路径高亮；新增工程作用域命令、receipt 与工作台快照一致性、同步失败仅重试读取；增加不 mock `@xyflow/react` 的 jsdom DOM 测试，验证实节点 wrapper、测量可见状态、候选 Handle、SVG edge 与键盘选择。Go 服务端单父/自连/成环/候选/幂等与运行锁测试通过。jsdom 测试不替代 WebView2 的真实尺寸、可见区域及 GUI 截图验收；真实窗口新增链路已由用户于 2026-11-04 手工确认，未启动真实 CLI，见 [M2-09 证据](evidence/m2-09.md)。

### M2-10A：选题参数与一次性运行

**实现**

- 选题卡编辑标题、想法、方向及 3～10 候选数；提供可访问的校验反馈。参数变更通过 `UpdateNodeParams` 保存；运行前等待待保存变更完成，失败时保留编辑内容并阻止启动，避免按旧参数执行。
- 节点入口调用 `RunService.Start(nodeId)`；防重复提交，展示 starting/running/终态、停止和错误，包括 CLI 不可用、`BUSY`、`NODE_LOCKED`、`RUNNING_CHAIN_LOCKED`、`CONTEXT_TOO_LARGE`（含可获得的估算/预算）。在途时禁止路径上的相关操作；运行结束或失败后以快照恢复实际锁状态。
- 如后端缺少可向 UI 传递估算/预算的结构化错误详情，增加最小只读错误信息并同步绑定和协议；不要根据错误文案猜测数值。运行完成不自动应用结果。

**测试与出口**：覆盖候选数边界、保存失败/连续修改竞态、保存完成后启动、双击启动、事件先于返回、运行失败/中断/锁释放、CLI 不可用、BUSY 与预算错误；锁定 topic 不可编辑或重跑。此项可用可控驱动验证运行；pending 的交互由 10B 完成。

### M2-10B：待应用与候选端口

**实现**

- 控制台待处理分页按当前工程/节点展示 pending；通过 `GetPending` 按需读取正文，兼容绑定的字节编码。有效 topics 预览候选，应用或丢弃后刷新快照；invalid 展示原文及校验错误，只允许丢弃。防重复提交，展示服务端错误；不把未应用内容当作节点轮次。
- `PARAMS_CHANGED`/`CONTEXT_CHANGED` 时展示明确差异警告，并由用户确认后才以 `force=true` 重试；其他错误不可强制绕过。运行锁、内容锁、Schema 和类型仍以服务端为准；取消保留 pending。
- 增加活动工程作用域的只读 `GetTopicCandidates(nodeId)`，从该 topic 最新已应用 `topics` round 引用的 artifact 读取候选，验证节点、round kind、artifact ID 和 payload；返回稳定 0 基索引及 `title/angle/hook`。不存在轮次时返回空列表，损坏/不可读时展示错误并禁用端口，不从 pending 或 artifact 元数据猜测候选。保持 Agent 侧 `read_artifact` 的路径过滤不变。
- 应用成功后重新读取权威候选，逐行显示输出端口，连接端口即选定 `parentCandidate`；支持同一候选多个分支和不同候选分支。画布不出现额外「选定」按钮；应用成功锁定 topic 内容与执行。

**测试与出口**：覆盖无效原文、候选预览、应用前图不变、应用/丢弃、重复点击、两个哈希冲突的确认/取消、其他错误不可 force、锁与 stale；覆盖候选读取跨工程、错误类型、缺失/损坏 artifact、刷新后与重启后可见、0 基索引、同候选/不同候选连线。AC-04、AC-07、AC-M2-3/4/12 分别记录已覆盖部分，不将提示词执行及真实 CLI 上下文验证标为通过。

### M2-10C：闭环集成自检

**实现与验证**
