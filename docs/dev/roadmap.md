## 1. 用途与权威

本文件回答三个问题：

1. 现在做什么：当前批次与需求优先级。
2. 做到哪了：批次与需求的状态。
3. 什么暂时不做：暂存需求池及其触发条件。

边界：

| 内容 | 归属文档 |
|---|---|
| 需求是什么、为什么做 | [PRD](../prd.md) |
| 需求怎么实现 | [架构](../architecture.md) / [ADR](../decisions.md) |
| 界面怎么呈现 | [前端设计](../frontend-design.md) |
| Agent 怎么接入 | [Agent 协议](../agent-protocol.md) |
| 做到什么算通过 | [验收标准](../acceptance.md) |
| 开发怎么推进 | [开发流程](process.md) |
| 怎么发版 | [发布规范](../release/) |

更新规则：

- 状态只能由用户确认后变更；变更必须有验收证据或明确决策。
- 不写开发日期、周数、工时或完成期限。
- 不删除已关闭条目；保留结论与原因。

## 4. 里程碑批次详情

任务分解见 [开发流程第 5 节](process.md#5-里程碑工作分解)；本节只记录范围、出口、依赖与风险。

### 4.1 M0 壳与绿色版

- **范围**：F-14；F-06 的 CLI 检测前置；M0 临时启动自检壳。
- **出口**：双击可用；不写 AppData；`data/`、`logs/`、`webview2/` 在 exe 同级；单实例；CLI 缺失有提示；版本与关于可见；最近日志可见。
- **依赖**：无。
- **风险**：Wails v3 API 变动；WebView2 不可用；exe 位于只读目录。
- **证据**：[M0 验收证据](evidence/m0.md)。

### 4.2 M1 Agent 会话

- **范围**：F-06、F-13；临时会话页/PromptDock、ask_user、Claude SDK/原生 CLI/agent host。
- **出口**：流式回复；工具行可见；权限允许/拒绝生效并审计；重启 resume；resume 失败可选新开会话；ask_user 可选择/其他/超时。
- **依赖**：M0（已完成）。
- **风险**：SDK/CLI 协议漂移；权限绕过；进程泄漏；Agent profile 例外。
- **证据**：[M1 验收证据](evidence/m1.md)。
- **状态**：已完成（0.2.0，用户验收通过）。F-06/F-13 在 M2 做运行级改造，M1 验收结论保留，回归验收见 AC-M1-1/2/5。

### 4.3 M2 图与提示词

- **范围**：M2-00～10 已验收旧模型作为历史基线；M2-11～13 按本地脚本目标推进：候选节点、prompt/agent 分离、合法 `topics` 自动生成候选、受限 `script` reply、输出版本确认、发送时快照；F-06/F-13 运行级改造回归。
- **出口**：单父树及新类型连接矩阵生效；topic 生成候选节点；prompt 仅构建任务；Agent 节点运行本地 Agent；合法脚本结果在无输出或空输出时自动写入，已有版本待确认并追加；运行路径/目标契约冻结；M1 流式/权限/问题卡回归通过。视频/云端不计入本批。
- **依赖**：M1（已完成）；M2-00～10（已验收，行为仍为旧模型）；M2-11A 设计评审已通过，M2-11B 已验收，M2-11C 已验收（2026-11-07）。
- **风险**：新旧工程版本边界、候选来源身份漂移、自动提交的事务/幂等、输出版本确认竞态、运行快照与实时图混用、RM-017 本地 Bash 协作式门禁残余风险。
- **状态**：已完成（用户于 2026-11-08 确认 M2 整体验收通过）。M2-00～10 旧模型及 M2-11～13 本地脚本目标均按对应验收记录完成；本批新目标验收以 AC-T-01～03、AC-T-05～10、AC-T-18～19 为准。AC-T-04 视频、AC-T-11～15/17 云端用例仍暂缓，不计入本批验收。0.3.0 版本及 S6 收口另行确认。

### 4.4 M3 渲染

- **范围**：F-08。
- **出口**：DSL 与画面一致；相同输入输出一致；应用后自动刷新；未知图层显式报错。
- **依赖**：M2。
- **风险**：渲染不确定；字体影响帧一致；Canvas 性能不足；DSL 迁移缺失。

### 4.5 M4 配音与导出

- **范围**：F-10（P0）、F-09（P1）。
- **出口**：P0 为 MP4、SRT、script.md 可生成且剪映可导入；P1 为配音时长驱动场景，不阻塞 P0 收口。
- **依赖**：M3。
- **风险**：H.264 不可用；音频时长漂移；字体/素材许可；导出性能。

### 4.6 M5 队列与回收站

- **范围**：F-11、F-12；日志面板收尾。
- **出口**：并发上限 3；排队可重排/取消；停止释放并发位；级联删除；24 小时恢复。
- **依赖**：M1–M4。
- **风险**：停止与出队竞态；级联遗漏；产物引用计数错误；过期清理误删。

## 7. 暂存需求池

### 7.1 定位

开发过程中出现、但当前无法处理的变动要求，统一进入本池。入池不等于拒绝，也不等于承诺；它保证要求不被遗忘，也不污染当前批次。

**入池条件（满足任一）**：

- 超出当前里程碑范围。
- 依赖未就绪（外部能力、协议、模型、格式）。
- 与已定 ADR 冲突。
- 成本或复杂度不适合当前批次。
- 需要外部版本或许可证评估。
- 用户提出但当前不规划。

**不入池**：

- 当前批次内的实现细节修正（走变更类型 A）。
- 阻断性问题（走缺陷流程，不压进池里）。
- 没有任何触发条件的空想（记录到讨论即可）。

### 7.2 字段

| 字段 | 说明 |
|---|---|
| ID | `RM-001` 起，不复用 |
| 标题 | 一句话说清能力 |
| 类型 | 需求 / 体验 / 技术债 / 风险 |
| 等级 | P0 / P1 / P2 / 待评估 |
| 来源 | 用户 / 开发 / 验收 / Agent / 外部依赖 |
| 提出日期 | 登记日期 |
| 影响 | F-xx、批次、文档、模块 |
| 暂缓原因 | 为什么现在不做 |
| 触发条件 | 什么情况下重新评估 |
| 建议版本 | v1.1 / v1.2 / v2 / 待定 |
| 状态 | 暂存 / 评估 / 已规划 / 已纳入 / 已拒绝 / 已废弃 |
| 关联 | ADR、PRD 条目、验收项 |

登记时追加到 [7.6 当前暂存条目](#76-当前暂存条目)：

```markdown
| RM-xxx | 标题 | 需求/体验/技术债/风险 | P0/P1/P2/待评估 | 建议版本 | 暂存 | 暂缓原因；触发条件 |
```

### 7.3 状态流转

```
暂存 → 评估 → 已规划 → 已纳入
  │       │
  ├───────┴──→ 已拒绝
  └──────────→ 已废弃
```

| 状态 | 含义 | 谁能改 |
|---|---|---|
| 暂存 | 已登记，当前不做 | 用户确认后登记 |
| 评估 | 正在判断可行性、成本、影响 | Claude 可提议，用户确认 |
| 已规划 | 已决定放入某个版本方向 | 用户 |
| 已纳入 | 已进入 PRD 与路线图，成为正式需求 | 用户 |
| 已拒绝 | 明确不做 | 用户 |
| 已废弃 | 条件消失或已被其他条目替代 | 用户 |

### 7.4 出池规则

条目从池中进入实现，必须依次完成：

1. 用户确认纳入。
2. 在 PRD 新增或修改 F-xx，并写变更记录。
3. 在验收标准补 AC。
4. 在路线图分配批次，状态改为「已规划」或「已纳入」。
5. 影响架构的，先新增 ADR。
6. 满足 DoR 后，才允许开工。

**不得**在未完成上述步骤时直接写实现代码。

### 7.5 评审规则

- 每个里程碑收口（S6）时逐条过池：保持、评估、规划、纳入、拒绝或废弃。
- 发版前确认没有「已规划但未纳入」的条目。
- 评审是事件驱动，不设日历周期。
- 同一需求重复出现时合并到原条目，不新建重复 ID。

## 9. 评审与更新规则

- **状态变更需证据**：AC 通过、评审记录、缺陷结论或用户明确决定。
- **评审触发**：里程碑收口、发版前、出现阻塞、用户要求；不按日历周期。
- **谁更新**：Claude 可起草与提议；状态与优先级由用户确认后写入。
- **不写时间**：不添加日期、周数、工时、完成期限；需要表达顺序时用批次与优先级。
- **不重复**：同一需求只保留一个 F-xx 与一个 RM-xxx；合并重复条目。
- **不删除历史**：已拒绝、已废弃条目保留，便于回看决策。
