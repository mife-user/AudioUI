## 实现摘要

- `workflow.SubmitRunReply` 只接受有效 v2 运行快照、冻结契约和活动运行锁。合法 `topics` 在单个可恢复 revision 事务中提交不可变 artifact、topic round/锁定、全部 Candidate 节点和回执。
- Agent `script` 无输出绑定时自动创建直接 Script 节点并写入首版；绑定空 Script 时自动写首版；已有版本时仅记录绑定目标和基准版本的 pending。确认时复核 Agent 参数/祖先哈希及输出绑定与基准版本；`force` 不绕过绑定或版本冲突，取消不改旧版本。
- 无效结构化 payload 保留有界原文；request ID 与同运行无 request ID 重放去重；不同身份/内容及并发结果明确冲突。MCP reply 保持原始 payload 和 `WithActiveRun` 租约；终结关闭开始后，pending observer 复用 reply 的在途租约完成索引/事件记录。仅 pending/invalid 结果写入运行 pending 记录。运行 pending 索引写入失败后，同 ID 重试会补存且不重复发布事件，不同 pending ID 冲突拒绝。
- `pending.txn.json` 以项目 revision 为提交点。未提交意图在加载时丢弃；已提交结果恢复前检查 Candidate/Script 图身份与 artifact/pending 关联，再幂等补齐 CAS 和 pending 索引。项目保存后若 pending 索引写入失败，仍广播已提交 revision 并更新活动运行锁 revision，同时保留 journal 供恢复；冲突时保留 journal 并拒绝加载工程。
