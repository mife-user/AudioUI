## 实现摘要

- 锁定 `@xyflow/react` 12.12.1；`WorkspaceCanvas` 受控渲染节点及由 `parent` / `parentCandidate` 派生的边，快照是图显示的权威来源。真实候选产物读取留至 M2-10B；M2-09 仅用 fixture 验证候选 Handle。
- AddNode、Connect、MoveNode、UpdateNodeParams、SelectNode 携带发起时的 `projectId`；服务端在写入前检查活动工程。图命令返回 `{ projectId, projectRevision, nodeId }`，前端只在同工程快照满足 revision 和目标节点条件后结束同步。
- 创建、连接和移动的“命令提交”与“快照呈现”分开建模。快照失败显示已提交、未同步，保存 receipt 并阻止重复写；「仅重试快照同步」不会再次提交图命令。工程切换丢弃旧 receipt；后端拒绝旧工程命令写入新工程。
- 新节点由占位矩形分配避让位置；快照确认后聚焦新增节点。工程初次载入/切换时 fit 一次，普通刷新不重置 viewport。既有已保存坐标不自动迁移。
- 工作台主区、画布与 React Flow 根使用确定的 flex 高度链和绝对填充；React Flow `onError` 转为可见错误。节点变更统一处理鼠标/键盘选择与位置更新；SelectNode 不递增工程 revision。
- 画布支持平移、0.6–1.6 缩放、重置视图、双击聚焦、位置防抖保存；失败位置回退到最后已保存值，切换工程时取消尚未提交的位置写入。
- 连线先调用 `Connect(..., replace=false)`。改挂确认显示子树数量、旧上游/候选、上下文变化及跨树 steps 迁移；提交期间禁止取消、背景关闭和 Escape。边只由服务端快照更新。
- 新增不 mock `@xyflow/react` 的 jsdom 集成测试，使用 `ResizeObserver` 和尺寸 stub 验证真实节点 wrapper 可见、候选 Handle、SVG edge 与 Enter/Space 键盘选择。该测试不替代 WebView2 实际布局和交互验收。

## WebView2 实测

- 早期观察：从 `bin/audio-ui.exe` 启动生产 Wails 窗口，使用隔离数据副本；窗口截图为 1440×900：[m2-09-webview-1440x900.png](m2-09-webview-1440x900.png)。当时工程 revision 为 4，渲染 3 个已持久化节点，证明 React Flow 并非整体空白；旧节点坐标约为 `(535,362)`、`(579,381)`、`(623,430)`，历史布局重叠，新分配器不会自动迁移旧存档。
- 2026-11-04 手工验收：在隔离数据副本中启动 `bin/audio-ui.exe`，通过真实窗口的键盘焦点依次触发「＋ 新选题」与「＋ 草稿提示词」。工程 revision 从 12 增至 14，节点从 4 个增至 6 个；界面状态显示「草稿提示词已同步。」，截图 [m2-09-webview-manual.png](m2-09-webview-manual.png) 显示 6 个节点均可见、位于画布内且互不重叠。未改写原 `bin/data`，未启动真实 Claude CLI。
- 手工截图证明创建命令、receipt 对应的快照同步和 React Flow 呈现链路在真实 WebView2 中工作；用户据此确认 M2-09 验收。
- 仍未手工覆盖：快照同步失败后「仅重试快照」、较小窗口、鼠标拖拽/滚轮缩放、方向键移动后重启持久化、改挂提交态。这些行为由 Go/前端自动测试与 jsdom 集成测试覆盖，但不等同于 GUI 手工验收。

缺陷回归：原先并发快照刷新时，`retryWorkspace()` 可能只排队下一次刷新便提前返回；当前通过回执验证工程 ID、持久化 revision 和目标节点，避免误把旧快照当作新节点已显示。同步失败保留已提交 receipt，重试仅请求快照，不再次创建。同步失败路径由前后端自动测试覆盖，真实窗口新建与同步链路已由用户手工验收。
