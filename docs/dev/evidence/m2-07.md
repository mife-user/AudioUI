## 实现摘要

- 新增 `service/run.Manager` 与 owner-aware `TurnGate`：启动前原子取得真实 topic 根到目标节点的工程快照和图锁；串行全局在途运行；终态清理 Agent、MCP、隔离配置、图锁和并发位。
- 每次运行创建新的 MCP 服务、随机 token、权限/问题 broker 与 CLI session；驱动从运行规格接收工具列表和 system prompt。项目切换在运行期间返回 `BUSY`。
- 将 `starting`/`running` 运行历史在启动恢复阶段改为 `interrupted`；transcript 最多保留 500 项，上下文预览最多 16 KiB；用首个 `AssistantMessage.Usage` 写回首次请求 input tokens 与 over-budget 状态。缺少该 usage 时字段未知，不以多轮累计的 `ResultMessage.Usage` 代替。
- 看门狗按 60 分钟无有效进展计时；流式/Agent 事件、MCP 操作和权限/问题应答都会重置。显式中断期间忽略 CLI 产生的 idle/error 终态竞争。
- Wails 发布 `run:<type>` 事件，事件携带 v、单调 seq、runId/treeId/chainId/nodeId/chainPath。终止先关闭权限 broker、拒绝新租约并等待已有 Agent/MCP 操作结束，再清理资源。
- M1 Agent Wails binding 暂留供前端迁移；旧 session service 不启动 Agent。运行工作台/前端订阅留 M2-08。

## 自审与未覆盖

- service 仅依赖 domain ports；handler 做输入转换并调用 `RunService`；新图写锁由 `service/workflow.BeginRun` 在 workflow mutex 下建立。
- Agent 不提供写图或 apply 工具；MCP 结构化结果仍只创建 pending，应用仍由 UI 命令完成。
- 启动、超时、中断、发送失败和关机路径都会尝试释放 TurnGate、图锁、per-run MCP 服务与配置；清理和存储错误会转成失败状态并记录日志。
- 真实 CLI 事件形状、Wails binding 解析、Windows 构建以及完整 AC-M2-9/11 GUI/端到端行为尚未验证，原因是外部 Go 模块不可下载且 M2-08/M2-13 UI 尚未实现。
- `Bash` 仍是协作式权限门禁，残余隔离风险按 RM-017 处理。
